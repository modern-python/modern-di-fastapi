# modern-di-fastapi 3.0.0 — modern-di 3.x

Requires **modern-di >= 3, < 4**. **No public API change** — `setup_di`,
`FromDI`, `build_di_container`, `fetch_di_container`, and the context providers
keep their signatures and behavior. The adapter already used the explicit
open/close container lifecycle (`async with` around the root and each
per-connection child), so no adapter code changed for
[modern-di 3.0's mandatory-open lifecycle](https://modern-di.modern-python.org/migration/to-3.x/).

## Changes

- **Bumped the `modern-di` dependency to `>=3,<4`.** Requires modern-di 3.x.
- **Adapted two tests to mandatory-open.** They built a child container and
  resolved from it without opening it; under 3.0 a container must be opened
  first, so they now use `with ...build_child_container()`. Test-only.

If your own code builds child containers, open them with `with` / `async with`
(or `open()`) before resolving — see the
[modern-di 3.x migration guide](https://modern-di.modern-python.org/migration/to-3.x/).
